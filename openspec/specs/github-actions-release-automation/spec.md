## Requirements
### Requirement: Pull requests targeting main are validated in GitHub Actions
The repository SHALL run GitHub Actions validation for pull requests whose base branch is `main`.

#### Scenario: Pull request to main triggers validation
- **WHEN** a pull request targets `main`
- **THEN** GitHub Actions starts the repository CI workflow for that pull request

### Requirement: GitHub Actions validation uses repository build tooling
The pull request validation workflow SHALL bootstrap the repository's Nix development environment and execute repository Taskfile entrypoints instead of ad-hoc shell build logic.

#### Scenario: Validation runs inside Nix with Task
- **WHEN** the pull request validation job executes
- **THEN** it installs Nix on the GitHub runner
- **AND** it enters the repository development environment with `nix develop`
- **AND** it runs repository validation commands through `task`

### Requirement: Tagged releases publish packaged artifacts
The repository SHALL publish a GitHub Release when a tag matching `v*` is pushed and the automated release build succeeds.

#### Scenario: Version tag publishes release assets
- **WHEN** a tag matching `v*` is pushed to the repository
- **THEN** GitHub Actions builds the configured release artifacts
- **AND** it uploads the generated packaged assets to the corresponding GitHub Release

### Requirement: Release automation preserves current artifact packaging
GitHub Actions release publication SHALL upload the packaged zip artifacts generated by `task build`, including the `wasm32-wasi-none` package.

#### Scenario: Release assets come from packaged build outputs
- **WHEN** the release workflow completes a successful tagged build
- **THEN** the uploaded assets are taken from `release/*.zip`
- **AND** the uploaded assets include the `wasm32-wasi-none` package when `task build` generates it successfully
