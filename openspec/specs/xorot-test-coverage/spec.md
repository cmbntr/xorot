## Requirements
### Requirement: ROT transformation boundaries are covered by automated tests
The project SHALL include automated tests that verify `rot` preserves its current byte transformation semantics for alphabetic ranges, numeric ranges, and non-mapped bytes.

#### Scenario: Alphabetic boundaries are verified
- **WHEN** the unit test suite exercises uppercase and lowercase boundary bytes for the ROT-mapped ranges
- **THEN** the tests verify that `A` through `M` and `a` through `m` map forward by 13
- **AND** the tests verify that `N` through `Z` and `n` through `z` map backward by 13

#### Scenario: Numeric boundaries are verified
- **WHEN** the unit test suite exercises boundary bytes for the numeric ROT-mapped ranges
- **THEN** the tests verify that `0` through `4` map forward by 5
- **AND** the tests verify that `5` through `9` map backward by 5

#### Scenario: Non-mapped bytes are preserved
- **WHEN** the unit test suite exercises bytes outside the alphabetic and numeric ROT-mapped ranges
- **THEN** the tests verify that those bytes are returned unchanged by `rot`

### Requirement: xorot stream behavior is covered by deterministic tests
The project SHALL include deterministic automated tests that verify `xorot` preserves current stream-processing semantics across empty, small, and multi-chunk inputs.

#### Scenario: Empty input produces empty output
- **WHEN** `xorot` is executed with an empty byte stream in a test harness
- **THEN** it produces an empty output stream

#### Scenario: Known byte vector remains stable
- **WHEN** `xorot` is executed against a fixed known input vector in a test harness
- **THEN** the produced output matches the expected byte-for-byte transformed result

#### Scenario: Chunk boundaries do not alter semantics
- **WHEN** equivalent input bytes are provided to `xorot` through test cases that cross the internal read buffer boundary
- **THEN** the resulting output matches the output produced for the same byte sequence processed without boundary-related variation

#### Scenario: Rolling XOR index wraps correctly
- **WHEN** a test input is long enough for the XOR index to advance past `0xFF`
- **THEN** the test verifies that the next processed byte uses index `0x00`
- **AND** the output remains consistent with the expected reference transform across the wrap point

### Requirement: xorot supports randomized invariant testing
The project SHALL include randomized or property-oriented tests that exercise binary byte streams and verify semantic invariants of the transform.

#### Scenario: Random binary inputs preserve output length
- **WHEN** randomized binary byte sequences are processed by `xorot` in automated tests
- **THEN** each produced output has the same length as its corresponding input

#### Scenario: Randomized outputs match the reference transform
- **WHEN** randomized binary byte sequences are processed by both `xorot` and a straightforward reference implementation in automated tests
- **THEN** the produced outputs are identical for each tested input

#### Scenario: Randomized tests are repeatable in default runs
- **WHEN** the default automated test suite is run repeatedly in the same source state
- **THEN** the randomized or property-oriented tests produce deterministic pass/fail results without flakiness from uncontrolled seeding

### Requirement: fuzz-style stress coverage is available to developers
The project SHALL provide a fuzz-oriented test path for repeatedly stressing `xorot` with generated byte streams without requiring changes to production behavior.

#### Scenario: Fuzz-style stress path exercises many generated inputs
- **WHEN** a developer runs the designated fuzz-oriented test path
- **THEN** the test harness executes `xorot` against many generated byte sequences
- **AND** it validates the same core invariants used by the randomized/property-oriented tests

#### Scenario: Fuzz-style path remains compatible with repository tooling
- **WHEN** the repository's documented test workflow is followed
- **THEN** the fuzz-oriented test path uses supported Zig tooling and repository build configuration

### Requirement: SIMD and scalar paths are covered by equivalent automated tests
The project SHALL include automated tests that verify the SIMD chunk path and scalar fallback path produce identical results for the same logical transform inputs.

#### Scenario: SIMD chunk boundary coverage is explicit
- **WHEN** the automated test suite exercises inputs around the chosen SIMD vector width boundary
- **THEN** the tests verify identical output for lengths below, equal to, and above that boundary

#### Scenario: Scalar fallback remains equivalent after vector chunks
- **WHEN** the automated test suite exercises an input that includes one or more full SIMD chunks followed by a non-empty tail
- **THEN** the tests verify that the tail output matches the reference transform exactly

### Requirement: SIMD-path wraparound behavior is protected by tests
The project SHALL include automated tests that verify rolling XOR index wraparound remains correct when processing spans SIMD chunk boundaries.

#### Scenario: Vectorized processing crosses the wrap point
- **WHEN** the automated test suite exercises an input long enough for the XOR index to wrap while full SIMD chunks are processed
- **THEN** the output matches the reference transform across the wrap point exactly

#### Scenario: Repeated runs stay deterministic after optimization
- **WHEN** the default automated test suite is run repeatedly after the SIMD optimization is introduced
- **THEN** the SIMD-related tests produce deterministic pass/fail results in the same source state
